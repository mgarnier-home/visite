# Visite — intégration continue : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ajouter un workflow « Tests » (PR et `main`) et un workflow « Publication » (tag
`vX.Y.Z`) au dépôt `mgarnier-home/visite`.

**Architecture:** `test.yml` tourne sur les runners GitHub avec trois jobs parallèles (back,
front, bout en bout) inspirés de `potixx`. `publish.yml` reprend `orchestrator-cli` : un build
natif par architecture sur les runners auto-hébergés, puis fusion multi-arch.

**Tech Stack:** GitHub Actions, `actions/checkout@v7`, `actions/setup-go@v7`,
`actions/setup-node@v7`, `actions/upload-artifact@v7`, `go-task/setup-task@v2`, Docker Buildx ;
`actionlint` v1.7.12 pour la vérification locale.

**Spec:** `docs/superpowers/specs/2026-10-25-ci-design.md`

## Global Constraints

- Branche `ci/workflows`. Commits autorisés, Conventional Commits, ligne `Co-Authored-By` du
  modèle qui écrit. Jamais de push.
- Noms et libellés en français (`name:` des workflows, jobs et étapes), commentaires en français
  sur les choix non évidents, comme dans `/mnt/dev/potixx/.github/workflows/`.
- Aucun nouveau secret ni variable. Aucune interpolation `${{ … }}` d'une donnée contrôlable
  (nom de tag) directement dans un script `run:` : passer par `env:`.
- Image : `mgarnier11/visite`, tags `<arch>`, `X.Y.Z`, `latest` ; cache
  `registry.mgarnier11.fr/visite:buildcache-<arch>` (`mode=max`).
- Runners : tests sur `ubuntu-latest` ; publication sur `linux/amd64` et `linux/arm64`.

## Review Focus

1. Un tag `v1.2` ou `v1.2.3-rc1` ne publie rien et le job échoue avec un message clair → vérifié
   dans Task 2 (lecture de la regex + exécution du script de validation à la main).
2. Un échec de bout en bout laisse un rapport téléchargeable → Task 1.
3. Deux push rapides sur une PR n'exécutent pas deux suites complètes → `concurrency`, Task 1.
4. `latest` n'est déplacé que par un tag valide → Task 2 (le job de fusion dépend de la
   validation).
5. Le binaire publié renvoie `vX.Y.Z` sur `/version` → Task 2 (build local avec les mêmes
   arguments et `curl /version`).

### Task 1: Workflow « Tests »

**Files:**
- Create: `.github/workflows/test.yml`

Contenu (spec §2) :
- `name: Tests` ; `on: pull_request` (branches `main`) et `push` (branches `main`) ;
  `concurrency` groupe `${{ github.workflow }}-${{ github.ref }}`, `cancel-in-progress: true` ;
  `permissions: contents: read`.
- Job `back` (« Back ») : checkout ; `actions/setup-go@v7` avec `go-version-file: backend/go.mod`
  et `cache-dependency-path: backend/go.sum` ; `go vet ./...` puis `go test -race ./...` avec
  `working-directory: backend`.
- Job `front` (« Front ») : checkout ; `actions/setup-node@v7` avec
  `node-version-file: .tool-versions`, `cache: npm`,
  `cache-dependency-path: frontend/package-lock.json` ; dans `frontend` : `npm ci`,
  `npx ng test --watch=false`, `npx ng build`.
- Job `e2e` (« Bout en bout ») : checkout ; setup-go et setup-node comme ci-dessus ;
  `go-task/setup-task@v2` avec `version: 3.53.1` ; `npm ci` dans `frontend` ;
  `npx playwright install --with-deps chromium` dans `frontend` ; `task e2e` à la racine ;
  `if: failure()` → `actions/upload-artifact@v7`, nom `playwright-report`, chemins
  `frontend/playwright-report/` et `frontend/test-results/`, `retention-days: 7`.

- [ ] **Step 1: Écrire `test.yml`.**
- [ ] **Step 2: Valider la syntaxe** — `go run github.com/rhysd/actionlint/cmd/actionlint@v1.7.12`
  à la racine → aucune erreur.
- [ ] **Step 3: Rejouer les commandes à la main** sur la VM (Go et Node déjà présents) :
  `cd backend && go vet ./... && go test -race ./...` ; `cd frontend && npm ci && npx ng test
  --watch=false && npx ng build` ; `task e2e` → tout passe.
- [ ] **Step 4: Commit** — `ci: run backend, frontend and end-to-end tests on pull requests`

### Task 2: Workflow « Publication »

**Files:**
- Create: `.github/workflows/publish.yml`

Contenu (spec §3) :
- `name: Publication`, `run-name: Publication de ${{ github.ref_name }}` ; `on: push: tags:
  ['v*.*.*']` ; `concurrency` groupe `${{ github.workflow }}-${{ github.ref }}`,
  `cancel-in-progress: false` ; `permissions: contents: read`.
- Job `version` (« Vérification du tag », `ubuntu-latest`) : `env: TAG: ${{ github.ref_name }}` ;
  échec avec `::error::Tag invalide « $TAG » : format attendu vX.Y.Z` si
  `! [[ "$TAG" =~ ^v[0-9]+\.[0-9]+\.[0-9]+$ ]]` ; sorties `version` (`X.Y.Z`) et `date`
  (`date -u +%Y-%m-%dT%H:%M:%SZ`) via `$GITHUB_OUTPUT`.
- Job `build` (« Image <arch> ») : `needs: version`, matrice `arch: [amd64, arm64]`,
  `runs-on: linux/${{ matrix.arch }}` ; checkout ; `docker buildx build` avec
  `--tag mgarnier11/visite:${{ matrix.arch }}`, `--build-arg VERSION=v<version>`,
  `--build-arg COMMIT=${{ github.sha }}`, `--build-arg DATE=<date>` (valeurs passées par `env:`),
  `--cache-from`/`--cache-to` du registre, `--push`, contexte `.`.
- Job `publish` (« Image multi-arch », `linux/amd64`) : `needs: [version, build]` ;
  `docker buildx imagetools create --tag mgarnier11/visite:<version> --tag mgarnier11/visite:latest
  mgarnier11/visite:amd64 mgarnier11/visite:arm64`.

- [ ] **Step 1: Écrire `publish.yml`.**
- [ ] **Step 2: Valider la syntaxe** — actionlint v1.7.12 → aucune erreur.
- [ ] **Step 3: Vérifier la validation du tag** — extraire le script du job `version` et
  l'exécuter avec `TAG=v1.2.3` (succès, `version=1.2.3`), `TAG=v1.2` et `TAG=v1.2.3-rc1`
  (échec avec le message).
- [ ] **Step 4: Vérifier l'image** — sur le contexte Docker local `default` uniquement (jamais
  apollon, athena, atlas, zephyr ; jamais de push) : `docker --context default buildx build
  --platform linux/amd64 --load -t visite:ci-check --build-arg VERSION=v9.9.9 --build-arg
  COMMIT=test --build-arg DATE=2026-10-26T00:00:00Z .`, lancer le conteneur sur un port libre
  avec un volume temporaire, `curl /version` → `v9.9.9` ; arrêter et supprimer conteneur, volume
  et image.
- [ ] **Step 5: Commit** — `ci: publish multi-arch docker image on version tags`
